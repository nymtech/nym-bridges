## [Unreleased]

### Added

- `ClientConfig::Amnezia` (`transport_type = "amnezia"`) in `transports_v2` of the client bridge descriptor for the AmneziaWG translator, one entry per protocol version. `transports` stays QUIC-only; clients that do not know the type drop it
- AmneziaWG 1.0 codec translating amneziawg-go datagrams to and from plain WireGuard
- AmneziaWG server config with per-bridge parameter generation
- `amnezia` transport listener in nym-bridge, with params generated by `bridge-cfg --gen`
- AmneziaWG 3.1 framing (`protocol_version = 2`): S3/S4 padding, H3/H4 ranges, header protection and trailers, served next to 1.0 on its own port
- AmneziaWG listener runs one SO_REUSEPORT socket per core on Linux, encodes replies into headroom without copying, and adds capped random trailers to 3.1 replies when enabled
- AmneziaWG 3.1 params with random trailers keep H3/H4 ranges at most 255 wide (wider ranges drop transport packets as false cookie replies); `bridge-cfg` generates single values
- AmneziaWG sockets request 4 MiB receive buffers, so long-RTT downloads no longer drop reply bursts from WireGuard. Operators: the Debian package installs `/usr/lib/sysctl.d/10-nym-bridge.conf` raising `net.core.rmem_max` to 4 MiB; it never lowers a higher value, and any later sysctl file overrides it. Other installs: set `net.core.rmem_max >= 4194304` (nym-bridge warns at start when it is lower)
- `bridge-cfg` generates AmneziaWG 3.1 params without random trailers: amneziawg-go pads every data packet with them, inflating metered uplink
- AmneziaWG sessions the node has not answered within 10 s are closed (a cookie reply does not count), so spoofed sources cannot fill the session limit
- nym-bridge and bridge-cfg name the first AmneziaWG parameter they refuse, such as `transport_pkt_junk_size` below the 12 byte nonce, and bridge-cfg skips an AmneziaWG block with unusable params instead of failing the refresh; a cookie reply (64 + `cookie_pkt_junk_size`) must now be smaller than the initiation (148 + `init_pkt_junk_size`)

## [0.3.0] - 2026-10-28

### Added

- `transports_v2` in the client bridge descriptor lists every transport (QUIC, TLS, SSH, and later ones). Both lists drop transport types the client does not know instead of failing

### Fixed

- SSH bridge sockets now go through `on_socket_open` like QUIC and TLS, so Linux and Android clients mark (fwmark) or bypass them instead of routing them into the tunnel

### Changed (breaking)

- `transports` in the client bridge descriptor now carries QUIC only, because released apps up to 2026.12 fail the whole gateway list on any other transport type. Clients read `PersistedClientConfig::advertised()` (falls back to `transports` for older bridges)
- `PersistedClientConfig` has a new field, `transports_v2`; code constructing it needs to set it
- Operators: upgrade from 0.2.2 to this release before enabling TLS or SSH; 0.2.2 advertises them in `transports`, which breaks apps up to 2026.12
- Update uniffi to 0.32.2 (https://github.com/nymtech/nym-bridges/pull/96); the client must use the same uniffi version
- Update dependencies and fix manifest lints (https://github.com/nymtech/nym-bridges/pull/99)
- Keep `utoipa` on 5.x: 6.0 changes the `ToSchema` trait that `nym-bridges-types` implements, which breaks consumers still on utoipa 5 (node-status-api)
